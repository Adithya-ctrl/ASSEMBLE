# ADR 0005: Civic Assembly Table direction

- Status: Accepted
- Date: 2026-08-29

## Context

The first integrated interface proved the solver journey but needed a coherent civic product direction. Several presentation models were evaluated.

| Alternative | Useful property | Rejected risk |
| --- | --- | --- |
| Assembly Table | Community warmth and event-day clarity | Could become an undifferentiated card dashboard |
| Constraint Blueprint | Strong technical visibility | Could feel cold or infrastructure-like |
| Evidence Story | Human explanation | Required excessive prose and annotation |
| Socket Assembly Board | Memorable block metaphor | Could become gamified or expensive responsively |

## Decision

Use the Assembly Table as the primary direction. Incorporate blueprint sockets and evidence rows, claim-adjacent proof, and shape-coded block cues without adopting a sales-page, generic dashboard, game, or infinite-canvas architecture.

## Consequences

- Community blocks remain visually primary.
- Technical proof stays adjacent to claims.
- The exact solver journey remains visible and response-gated.
- Current visual and accessibility behavior is maintained in `docs/UI_DIRECTION.md` and `docs/reference/accessibility.md`.
