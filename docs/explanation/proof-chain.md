# From community capacity to an executable Project

ASSEMBLE separates a plausible intervention from a proved operational plan.

1. The compiler translates declared people, capabilities, languages, availability, venue features and capacity, resources, and time into a bounded CP-SAT model.
2. A feasible result contains a complete assignment and assembly trace. UNKNOWN and INFEASIBLE contain no witness.
3. Explanation identifies small requirement groups whose bounded relaxation restores feasibility; it does not invent a narrative answer.
4. Unlock compares the finite disclosed catalyst catalogue and returns the minimum sufficient modelled intervention.
5. Transition applies the chosen authoritative action to a copy and returns an immutable successor plus explicit diff.
6. Verification solves that successor independently. Until this succeeds, the initiative remains blocked in the interface.
7. Project creation starts again from authoritative S0, replays the submitted 0–2 action path, and performs a fresh solve.
8. Only a complete feasible witness becomes operational assignments, schedule, venue, resource allocation, language capacity, accessibility, and readiness evidence.

This double proof is intentional. The interface proof controls when the form appears; the creation endpoint does not trust that UI state and proves the plan again.

Basic Workshop demonstrates a valid empty catalyst path. Multilingual Clinic demonstrates a one-action successor path. Both produce the same Project shape because execution information is derived from the witness rather than from hand-authored fixture-specific answers.
