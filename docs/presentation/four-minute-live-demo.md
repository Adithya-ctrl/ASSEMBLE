## Time checkpoints

- **1:00:** Basic proof complete; Clinic selected.
- **2:00:** minimum unlock explained; APPLY beginning.
- **3:00:** successor verified; Project form in progress.
- **3:40:** source proof visible.
- **4:00:** Reset and boundary statement complete.

## Reset-based recovery

If the selected initiative, state header, or downstream panels do not match the speaking point, say: “I’m returning to the authoritative baseline so the proof chain is unambiguous.” Activate Reset once, confirm S0 and cleared panels, then resume at Basic or Clinic. Do not manually conceal stale panels or describe an unverified state as feasible.

## Shortened fallback for a stalled action

If a local request or screen action stalls, stop repeated clicks. Use this 45-second close while keeping the last truthful state visible:

1. “The current visible state is the last confirmed response; ASSEMBLE never advances optimistically.”
2. Point to the Technical Inspector or current status and summarize only evidence already visible.
3. State the remaining expected chain conditionally: “After a verified OPTIMAL successor, the server can replay the path and derive a Project.”
4. Show the requirements, current build status, or prerecorded clean journey only if competition rules allow it.
5. Close with the bounded fixture and absent-capability statement.

Do not pretend every internal field can be narrated in four minutes. Prioritize the blocker facts, minimum-action comparison, immutable transition, separate verification, server-derived Project, source proof, full feature parity, and honest limits.
